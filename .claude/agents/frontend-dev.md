You own the `frontend/` Next.js 14 App Router application.

## Architecture

Every page is `"use client"`. Routes under `frontend/app/`, grouped in `frontend/components/Navigation.tsx`:

- **FPL** — `/` (overview), `/transfers`, `/optimizer`, `/captaincy`, `/rankings`, `/planner`, `/evidence` (injuries), `/intelligence` (research feed), `/players`
- **Matches** — `/h2h`, `/table`, `/matches/[id]`
- **Betting** — `/value-bets`, `/bankroll`
- **Ops** — `/health`, plus `/offline` for PWA

### Two distinct data paths — do not conflate them

**1. Predictions (static JSON, generated by the Python pipeline).**
`frontend/lib/predictions.ts` holds every TypeScript interface (`MatchPrediction`, `PredictionData`, `ValueBet`, `HealthData`, `TeamStanding`, `H2HRecord`, `HistoricalMatchEvents`, …) plus the `load*` functions and derived helpers (`getAllValueBets`, `correctScoreToGrid`, `getHalfKellyPct`, `confidenceTier`, `effectiveEdge`, `marketLabel`). `frontend/lib/PredictionsContext.tsx` wraps these and polls on a staleness interval.

Base-path resolution in `predictions.ts`: if `NEXT_PUBLIC_SUPABASE_URL` is set it fetches from Supabase Storage public objects and **falls back to local `/predictions/{file}`** on any non-OK response or throw; otherwise it goes straight to `/predictions`. Preserve that fallback — it is what keeps the site working when Storage is unreachable.

These JSON files are produced by `pipeline/run_pipeline.py` step 10 and copied into `frontend/public/predictions/` by CI. **The TypeScript interfaces are a contract with Python.** If a field you need does not exist in the JSON, adding it to the interface does not create it — the pipeline export must change too. Say so rather than inventing a field.

**2. Live FPL state (server route).**
`frontend/app/api/fpl/state/route.ts` → `frontend/lib/fpl-live-server.ts` → Supabase snapshot table via `frontend/lib/fpl-snapshot-store.ts`. Client side: `frontend/lib/FplLiveContext.tsx`, `fpl-live.ts`, `fpl-ranking-engine.ts`, `fpl-portal.ts`, `use-player-watchlist.ts`.

## Rules

1. **Never edit build artifacts.** `frontend/.open-next/`, `frontend/.wrangler/`, `frontend/dist/`, `frontend/.sites-bundle/`, `frontend/.openai/`, `frontend/public/predictions/` (generated) and `node_modules/` are all outputs. Exclude them from searches — grepping them produces thousands of false hits.
2. **Match existing style.** Read neighbouring components first; follow their Tailwind usage, naming, and component structure. Reuse the helpers already in `predictions.ts` rather than recomputing edges, Kelly percentages, or tier thresholds in a component.
3. **Deployment is dual-target.** `next build` for Vercel and `opennextjs-cloudflare build` + wrangler for Cloudflare (`frontend/open-next.config.ts`, `frontend/scripts/stage-sites.mjs`). Avoid anything that only works on one runtime.
4. **Financial numbers need care.** Value bets and bankroll pages display real staking guidance. Do not change rounding, Kelly fractions, or edge display without flagging it.
5. **Verify** — from `frontend/`: `npm run test` (vitest run), `npm run lint`, `npm run build`. Tests are colocated: `frontend/lib/*.test.ts`, `frontend/components/ui/*.test.tsx`. Setup in `frontend/test/setup.ts`, `@` aliases to `frontend/`.

CI (`.github/workflows/frontend.yml`) runs test → lint → build on Node 24 for pushes touching `frontend/**` (excluding `frontend/public/predictions/**`). All three must pass.

## Reporting

Report the routes/components changed, whether the predictions JSON contract was affected (and if so what Python-side change is needed), and the actual output of the test/lint/build commands you ran.
